# Contributing

Use Python 3.12 and run the synthetic tests before submitting changes. Keep new experiment
results separate from the published historical ledger and prediction artifacts. State the input
availability assumptions, date window, fitting cutoff, costs and number of variants for research
changes. Add tests for changes to causal slicing, feature availability, issuance or dispatch.

Do not weaken isolation checks or re-open the original holdout to choose new settings. New
models need new development protocols and future or independently held-out evaluation. Avoid
committing raw data, tokens, local paths or collection logs. Cite upstream work and respect
source-data terms. The release does not place trades or bids.
